# Decision 021: How the multi-Crawler rules are built (status, session marker, swap, delete, reskins)
Owner: Borent Corp Systems Architect | Status: final | Version: 1.0 | Updated: 2026-10-04
Summary: Implementation choices for decision 020 and spec section 8.4: `status` field, `session-status` marker, request/activate swap with a per-window limit, `crawler delete` order of operations and archive, one channel per Crawler with overflow categories, item names from the single-source item-reskins table with variant picks.

- **Why a separate decision.** Decision 020 (Syndicate, Caleb's rulings) says what the rules are. This one records the choices the Architect made where the spec left them open. None changes a ruling.
- **Status.** `crawler.status = active|benched` on player Crawlers and pet-Crawlers (pets follow their owner). First Crawler of a human = active; later = benched. "Same human" = same `build.discord_user_id`, else same `player` name (lowercased), so Horn and Bone (no recorded Discord id) still group by name. `state.py crawler migrate` fills missing statuses once.
- **Session marker.** There was no session-status record. `state.py session-status open|close|show` writes `<data>/session-status.json` (also a window counter `opens`). A session is open when that file says so or a fresh GM lock exists. The bridge `/join` opens and `/leave` closes it (best effort). Cost: if the bridge dies in voice, the marker stays "open" until `session-status close`; the GM routine should still open/close it explicitly.
- **Swap.** The player side (`/crawlers`) only files a REQUEST (`swap-requests.jsonl`); the GM runs `crawler activate`. Both refuse while a session is open; refusals are written to `swap-log.jsonl`. One swap per player per window (window = number of session opens so far); the pick that follows deleting the active Crawler is not counted; `--override-window WHY` lets the GM allow another. Transfers between a player's own Crawlers are refused outright (no override), so a benched Crawler cannot be a mule and starting credits only ever come from the Crawler's own `/create`.
- **Delete.** Housekeeping, no flag, no penalty; the delete log prints the player's delete count for the floor. The typed Crawler name is required by the tool as well as by `/delete`. Order: archive ledger rows, remove them from the live ledger (tmp + rename), backup + validate + write state, move the sheet file, clean the sheet map and snapshots, delete the channel, append the log. A crash between steps leaves rows in the archive and in the ledger (deduplicated by `seq` on retry). Story Box slot: a `released` event in the story-box ledger (cap check ignores released boxes) unless a living Crawler still holds one of the box's items; the deed registry is untouched, so the deed cannot pay twice.
- **Biscuit rule.** One conversion per LIVING pet-Crawler; no tombstone (Caleb, confirmed). Deleting a pet-Crawler frees the conversion; a new one needs a new Enhanced Pet Biscuit.
- **Channels.** One text channel per Crawler `<player>-<crawler>` (pets `<player>-<pet>-sheet`), unique names (`-2`, `-3`), warn at 45 channels in a category, overflow categories `Crawler Sheets 2`... at 50. Existing mappings keep their channel and name. The sheet map stays in `player-channels.json`, keyed by Crawler name, with an `owner` field (the spec asks for it in `state.json`; kept in the existing map file to avoid a second source of truth for channels).
- **Item names.** `tables/item-reskins.json` (Lore) is the single source, linked by symlink from `tables/` with its version file; the sha256 is checked by `tools/reskin_check.py` (test) and at bridge start (warning). The sheet stores `srd_id` and `chargen_key` on every inventory row. Labels come from `combined_label`, then legacy name, then the plain 5e name, never blank. Chargen's `junk` field is not read. Header items (`holy_symbol`, `gaming_set`, `musical_instrument`, `artisans_tools`, and any generic marked `resolve_to_variant`, e.g. `arcane-focus`, `druidic-focus`) are never shown priced, stored or committed: the gear screen asks for a variant, the price is that variant's `base_price_cp` (Vending Wall x the floor multiplier of the current floor; package gold is not scaled), and the commit refuses a stray header row. Pre-built Crawlers take the first listed variant.
- **Decided by Caleb or Syndicate, not here:** one active Crawler per player, session lock, `/delete` rules, Story Box slot freed, layout (decision 020).
